# 04 · 里程碑、测试、上架与风险

## 1. 里程碑

### M0 · 技术验证 spike(3–5 天)——先证伪,再投入

目标:用最小代码回答三个最高风险问题——**提取质量够不够、轮廓观感行不行、坐标换算对不对**。

- [ ] 单页 demo:PhotosPicker 导入 → 骨架 + 轮廓叠回原图显示
- [ ] 跑 20 张标准测试集(§2),记录每张的关节数/轮廓质量
- [ ] 相机页画一条静态轮廓,接上缩放/拖动/旋转/镜像手势
- [ ] 实测 03·§8 性能预算并修订

**通过标准**:常规站/坐姿 10/10 可用;复杂姿势(蹲/趴/遮挡)≥ 5/10;轮廓平滑度目测可接受。
**不通过时**:先调分割质量档与 epsilon;仍不行→提前启动 §5.1 Core AI 评估,或收缩 MVP 只支持常规姿势。

### M1 · MVP 开发(2–3 周)

- 周 1:提取管线完整化(多人点选、失败兜底、模板库存取)+ PoseKit 单测
- 周 2:相机页(会话管理、叠加渲染、手势、拍照保存)+ GeometryMapper 用例矩阵
- 周 3:打磨(空态/文案/图标)、TestFlight 内测 ≥ 10 人、按反馈修一轮

**退出标准**:01·§7 验收全绿;崩溃率 0;内测者能独立完成"导入→拍出同款"。

### M2 · 上架(1–2 周)

- onboarding 3 屏(演示核心旅程)、App 图标、5 张商店截图 + 15s 预览视频
- ASO:标题「摹拍 PoseTrace - 姿势轮廓相机·照着拍同款」;关键词覆盖:拍照姿势/摆pose/拍同款/轮廓相机
- 隐私标签(§3)、审核备注 + 演示视频、提审

### M3+ · 迭代

P1 功能包(01·§4)→ P2 实时匹配(03·§7)→ Core AI 升级(§5.1,按触发条件)。

## 2. 测试策略

**标准测试集(20 张,入库 `Tests/Fixtures/`)**:全身站姿×4、坐姿×3、侧身×2、蹲/趴×2、半身×3、遮挡(手挡脸/交叉腿)×3、多人×2、低对比/暗光×1。
来源必须无版权风险:自拍或 CC0 图库;每张配期望结果 JSON(首跑生成后人工核对 = 金标准)。**这套集合与期望值未来直接平移给 Android 端做双端一致性验收(§5.2)。**

| 层 | 内容 |
| --- | --- |
| 单元测试 | GeometryMapper(方向×镜像×aspect 用例矩阵,全纯函数);ContourBuilder(fixture mask → 点数/包围盒断言);TemplateStore(读写回环、损坏文件恢复) |
| 提取回归 | fixtures + 期望 JSON,容差比较(容差 2% 图像对角线——Vision 随系统升级可能微调输出) |
| 真机矩阵 | 最老支持档(A12 · iPhone XR/XS)+ 主流(13/15)+ Pro Max 大屏;查发热、前摄镜像、横竖屏、灵动岛遮挡 |
| 性能 | Instruments:Time Profiler + Core Animation FPS,对照 03·§8 预算 |

## 4. 风险登记表

| 风险 | 等级 | 缓解 |
| --- | --- | --- |
| 复杂姿势提取质量不达标 | 高 | M0 前置证伪;失败日志攒证据;备选 §5.1 |
| 坐标/镜像换算 bug 反复出现 | 高(频率) | 02·D7 单一坐标表示 + GeometryMapper 纯函数 + 用例矩阵 |

| 内置姿势库版权 | 中 | P1 才引入;采购授权或自制剪影素材(参考 SOVS 模式) |
| 轮廓锯齿/观感差 | 中 | 二值化 + epsilon 调参 + 渲染平滑;M0 目测验收 |

## 5. 演进路径

### 5.1 何时引入 Core AI + 自选模型

**触发条件(满足其一)**:失败日志中复杂姿势占比 > 20%;竞品在难姿势上可感知领先;P2 实时匹配的精度不够用。

**做法**:
1. `PoseExtractor` 自始就实现 `protocol PoseProviding`(Vision 是第一个实现)。
2. 新增 `CoreAIPoseProvider`:候选模型 RTMPose/ViTPose 系 → PyTorch 转 Core AI 格式 → ANE 推理;分割侧同理(SAM 系轻量版)。
3. **双 Provider 输出同一关节拓扑**(必要时加拓扑映射层),`PoseTemplate` 格式不变,老模板零迁移。
4. Vision 实现保留,作为老机型/低系统兜底。

### 5.2 Android(iOS 验证成功后)

- 引擎:MediaPipe Tasks 或 LiteRT + 与 iOS 相同的自选模型——**双引擎、单模型、单拓扑**。
- 直接复用:关节拓扑与连线定义、匹配打分算法、20 张金标准测试集与期望值。
- 重写:UI、相机管线(CameraX)。

### 5.3 远期(不承诺)

姿势重定向(按被拍者身材变形参考骨架)、3D 姿态(`VNDetectHumanBodyPose3DRequest`)辅助机位建议、iPad 适配。明确不做:Mac Catalyst。
