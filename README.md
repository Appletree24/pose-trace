# PoseTrace(摹拍)· iOS 实现方案

> 导入一张参考照片 → 自动提取人物姿势(骨架 + 轮廓线)→ 相机取景实时叠加 → 引导被拍者摆出同款姿势 → 拍照。

- 范围:仅 iOS(Android 规划见 [docs/04](docs/04-plan-and-risks.md) §5.2)
- 状态:P0 骨架 + P1 部分功能(幽灵模式/网格/水平仪/收藏/重命名/前摄镜像保存),2026-09-21
- 假设:单人开发 + AI 编码辅助;API 以 iOS 17–18 SDK 为准,动工时用 Xcode 文档逐一核对

## 核心决策速览

| 决策 | 选择 | 一句话理由 |
| --- | --- | --- |
| 最低系统 | iOS 17.0 | 需要多人实例分割等 API;省掉兼容分支(详见 02·D1) |
| 语言 / UI | Swift + SwiftUI(相机预览包一层 UIKit) | 开发效率最高;相机核心仍是原生管线 |
| AI 能力 | 系统 Vision 框架 | 零模型工程、零推理成本、全端侧隐私(详见 02·D3) |
| MVP 相机 | 无逐帧推理:静态矢量叠加 + 手势对齐 | 60fps 稳、功耗低、机型下限友好(详见 02·D4) |
| 第三方依赖 | 0 个 | 系统框架全覆盖,减少维护与审核面 |
| 持久化 | Codable JSON + 文件系统 | 模板量级小,数据库是过度设计(详见 02·D5) |
| 升级路径 | Vision 触到精度天花板后切 Core AI + 自选模型 | 触发条件与做法见 04·§5.1 |

## 实施节奏

M0 技术验证(3–5 天)→ M1 MVP(2–3 周)→ M2 上架打磨(1–2 周)→ M3+ 迭代(P1 功能包 → P2 实时匹配 → Core AI 升级)。详见 docs/04。
